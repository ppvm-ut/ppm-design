# Правила работы в проекте PPM_Design

## Формат итоговых материалов

- По итогам содержательных задач по умолчанию создавай или обновляй готовый HTML-артефакт. Применяй это правило ко всему проекту и его подпапкам.
- Для интерфейсов и прототипов итоговым артефактом должен быть работающий HTML с результатом запрошенных изменений. Для исследований, планов и аналитических задач оформляй результат как HTML-документ с выводами и источниками, если они использовались.
- Используй русский язык, если пользователь не запросил другой язык или содержание существующего интерфейса не требует иного.
- Создавай самостоятельный HTML, который открывается в браузере без установки зависимостей и сборки. По возможности встраивай стили, скрипты и необходимые ресурсы. Если нужны отдельные файлы, сохраняй их рядом и используй относительные пути.
- Используй адаптивную вёрстку и добавляй интерактивность, когда она помогает понять или проверить результат.
- Новые HTML-прототипы сохраняй в `/Users/worker/Desktop/PPM_Codex/PPM_Design/prototypes/` с понятными именами; отдельный сценарий можно оформить подпапкой с `index.html` и ресурсами. Остальные итоговые материалы сохраняй непосредственно в корне проекта. Если задача состоит в изменении существующего HTML-файла, обновляй этот файл, если пользователь не указал другое место.
- Перед выдачей проверяй целостность HTML, доступность ресурсов и работу изменённых элементов; при наличии инструмента предпросмотра проверяй отображение в браузере.
- В итоговом ответе давай ссылку на готовый HTML-файл и краткое резюме результата. Не ограничивайся блоком HTML-кода в чате.
- Для коротких уточнений, ответов о ходе работы и служебных изменений настроек отдельный HTML не требуется.
- Явный запрос пользователя на другой формат имеет приоритет; создавай HTML дополнительно только если это полезно и не противоречит запросу.

## Каталог и GitHub Pages

- Репозиторий проекта: `https://github.com/ppvm-ut/ppm-design`. Основная ветка публикации — `main`.
- Корневой `index.html` — автоматически генерируемый каталог. Не заменяй его отдельным прототипом. Его шаблон и правила сборки находятся в `scripts/build_pages.py`.
- Новые HTML автоматически включаются в каталог при сборке. Указывай осмысленный `<title>`, сохраняй относительные пути к ресурсам и уникальные ключи браузерного хранилища.
- Перед отправкой изменений запускай `python3 scripts/build_pages.py` и проверяй предупреждения о недостающих ресурсах. Не добавляй `_site/` и `work/` в Git.
- После push в `main` workflow `.github/workflows/pages.yml` публикует сайт на GitHub Pages. Сохранение файла локально не означает, что он опубликован. Сообщай фактический статус отправки и деплоя.

## Каталог HTML-прототипов

- Правила публикации и метаданных — `prototypes/README.md`.
- `prototypes/index.html` и `prototypes/catalog.json` генерируются из HTML-файлов при запуске `scripts/build_pages.py`; вручную списки не редактировать.
- База отдела `wiki/notes/prototypes.md` ссылается на веб-каталог. Не заводи в ней параллельный список файлов и статусов; решения и согласования сохраняй в базе или задаче и связывай через метатеги.
