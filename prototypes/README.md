# HTML-прототипы

Папка для публикации самостоятельных HTML-прототипов и их ресурсов.

- [Открыть общий каталог](https://ppvm-ut.github.io/ppm-design/)
- [Технический пример](https://ppvm-ut.github.io/ppm-design/prototypes/example/)

## Добавление

1. Создайте `prototypes/<slug>.html` или `prototypes/<slug>/index.html`. В имени используйте латинские буквы, цифры и дефисы. CSS, JS и картинки размещайте рядом, с относительными путями.
2. Укажите `<title>` и описание. По умолчанию статус — черновик. При необходимости добавьте метатеги ниже.
3. Выполните `python3 scripts/build_pages.py` из корня репозитория. Исправьте предупреждения, относящиеся к новому прототипу.
4. Сохраните файлы прототипа и обновлённые `index.html`, `prototypes/catalog.json` в Git и отправьте в `main`.
5. Дождитесь успешного workflow **Publish prototypes to GitHub Pages**. Только после этого проверьте прямую ссылку: `https://ppvm-ut.github.io/ppm-design/prototypes/<slug>.html` или `https://ppvm-ut.github.io/ppm-design/prototypes/<slug>/`.

GitHub Actions выполняет ту же сборку. Новый HTML автоматически попадает в веб-каталог; ручное добавление строки в базу отдела не требуется. Каталог базы ведёт на этот список и его фильтры. Главный каталог проекта продолжает показывать и ранее опубликованные файлы.

## Метаданные в HTML

```html
<title>Название прототипа</title>
<meta name="description" content="Что проверяем в этом сценарии">
<meta name="prototype-status" content="draft">
<!-- Необязательно: полные ссылки на реальные материалы -->
<meta name="prototype-task" content="https://tracker.yandex.ru/PPT-123">
<meta name="prototype-figma" content="https://www.figma.com/design/FILE/">
```

Статусы: `draft` — черновик, `review` — на проверке, `approved` — согласован, `archived` — архив. Для `approved` обязательна ссылка `<meta name="prototype-approval" content="https://...">` на реальное согласование. Примеры URL выше замените своими или удалите соответствующие метатеги.

Согласование и содержательные решения фиксируются в задаче или базе отдела. Метаданные каталога лишь ссылаются на них. Статус «архив» не удаляет страницу и не ограничивает доступ.

`catalog.json` генерируется автоматически из HTML. Логика — `scripts/build_prototypes.py`. Общий каталог проекта собирает `scripts/build_pages.py`. Дополнительная страница `prototypes/index.html` удалена.

## Доступ и ограничения

Сайт и репозиторий публичные, как и существующая площадка PPM Design. Здесь размещаются демонстрационные интерфейсы без персональных данных и секретов. Ссылка на базу отдела требует её корпоративного доступа.

Публикуется только статика: HTML, CSS, JS и веб-ресурсы. Серверный код не выполняется. Ключи браузерного хранилища должны быть уникальными для прототипа. Действующие ссылки на старые прототипы в корне проекта сохраняются.
